SECTION 6: AUDIT OF THE CLEANING SCRIPT (scripts/clean_welfake.py)
================================================================================
1. The Transformation Applied in clean_welfake.py:
   Lines 210-213:
     ```python
     df["raw_label"] = df["label"].astype(int)
     df["label"] = df["raw_label"].apply(lambda x: 1 if x == 0 else 0)
     df["label_name"] = df["label"].apply(lambda x: "Real" if x == 1 else "Fake")
     ```

2. Column-by-Column Alignment in data/processed/WELFake_cleaned.csv:
   -----------------------------------------------------------------------------
   Column Name | Value Type | Mapped Value | Ground Truth Meaning | Record Count
   -----------------------------------------------------------------------------
   label       | int64      | 1            | Real News            | 34,788 (55.58%)
   label       | int64      | 0            | Fake News            | 27,798 (44.42%)
   label_name  | str        | 'Real'       | Real News            | 34,788 (55.58%)
   label_name  | str        | 'Fake'       | Fake News            | 27,798 (44.42%)
   raw_label   | int64      | 0            | (Original Raw Value) | 34,788 (55.58%)
   raw_label   | int64      | 1            | (Original Raw Value) | 27,798 (44.42%)
   -----------------------------------------------------------------------------
   Total Clean Records: 62,586 (100.0%)

3. Is this transformation justified?
   YES, and it is standard practice in binary classification for fake news detection:
   - In machine learning literature, the positive class (1) typically denotes authentic/true,
     while 0 denotes synthetic/false (or vice versa in anomaly detection).
   - In scikit-learn metrics (Precision, Recall, F1-Score), treating 1 as the target class
     is the default expectation.
   - Most importantly, the inclusion of the explicit textual column 'label_name' ('Real' / 'Fake')
     guarantees that downstream model training pipelines CANNOT misinterpret the class labels,
     even if an engineer forgets the numerical mapping.
